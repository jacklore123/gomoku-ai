# 算法说明

## 总体思路

五子棋 AI 不追求暴力搜索所有 361 个格子，而是采用“局部候选 + 深度优先搜索 + 棋形评估”的方式。这样在普通笔记本上也能保持较低延迟，同时具备明确的攻防能力。

## 1. 棋盘表示

引擎内部使用一维 `list[int]` 保存棋盘：

- `0` 表示空
- `1` 表示黑棋
- `2` 表示白棋

同时维护黑棋、白棋两张位棋盘（Python `int`），用于快速生成候选点和整盘评估。

## 2. 候选点生成

合法落子虽然很多，但真正有价值的点通常集中在已有棋子附近。程序预计算每个格子周围 2 格范围内的邻域掩码，每次只生成这些邻域中的空点。这样在 19×19 棋盘上，中盘通常只需要考虑几十到一百个点。

## 3. 棋形评估

评估分为两层：

### 3.1 单点精细评估

对每个候选点，沿着横、竖、两条斜线分别检查 5 格和 6 格窗口，识别：

- 成五
- 活四 / 冲四
- 活三 / 眠三
- 活二 / 眠二

再把四个方向组合成双活三、四三等复合威胁。这个评估用于根节点的战术短路和关键落点排序。

### 3.2 整盘位棋盘评估

搜索叶子节点使用预先计算好的所有六连窗口。对每个窗口，用位棋盘快速统计黑白棋子数量、窗口两端是否开放，再累加双方棋形分数。这样避免在叶子节点对每个候选点重复做昂贵的字符串分析。

## 4. 搜索

搜索使用：

- **Negamax + Alpha-Beta 剪枝**：标准对抗搜索框架。
- **迭代加深**：从深度 1 逐步加深到最大深度，时间耗尽时保留上一轮完整结果。
- **Zobrist 置换表**：缓存已经搜索过的局面，避免重复计算。
- **着法排序**：内部节点使用快速连续子计数排序，显著提高剪枝效率。
- **时间控制**：搜索过程中定时检查截止时间，超时立即安全回溯。

## 5. 战术短路

在每一步根节点：

1. 如果自己有成五点，直接获胜。
2. 如果对手有成五点，直接堵住。
3. 否则进入迭代加深搜索。

这样可以避免简单的“看漏一步杀”，也让开局和残局响应更快。

## 6. 三档棋力

| 档位 | 最大深度 | 每步时间上限 | 候选分支上限 |
| --- | ---: | ---: | ---: |
| 低 | 2 | 0.25 秒 | 12 |
| 中 | 4 | 0.80 秒 | 20 |
| 高 | 6 | 2.00 秒 | 28 |

这些参数可在 CLI 中用 `--depth`、`--time`、`--branch` 手动覆盖。

## 7. 为什么不是 MCTS

蒙特卡洛树搜索在部分棋盘游戏中表现很好，但五子棋存在大量强制点（成五、堵四），纯随机模拟容易漏算。Alpha-Beta 配合棋形评估在这种战术密集的棋类中更直接、更可控，也更容易在 Python 中实现较低的延迟。
